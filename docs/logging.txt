DEBUG LOGGING
=============

Debug logging is always on. It cannot be switched off.

Where the logs are
------------------
  %TEMP%\Debug\office-install-tool\<yyyy-MM-dd>
  (usually C:\Users\<you>\AppData\Local\Temp\Debug\office-install-tool\<yyyy-MM-dd>)

What is written there (one file per window)
-------------------------------------------
  debug-launcher-<HHmmss>.log           the first window, before the administrator relaunch
  debug-install-<HHmmss>.log            the elevated main window (menu, questions, install)
  debug-Test-OfficeInstallReadiness-<HHmmss>.log   the readiness-check window (menu option 2)
  debug-Remove-OfficeLeftovers-<HHmmss>.log        the scan / cleanup window (menu options 3 and 4)
  officesetup-<PC>-<date>.log           Office's own setup logs, copied from %TEMP% when the install ends
                                        (the Office installer window cannot be transcribed)

Each window starts its own transcript and stops it when it ends, including after an error.
Every run makes new files; old files are never overwritten.

Other logs
----------
  - Office's own setup logs: %TEMP%\<PC name>-<date>.log (product keys redacted).
  - Job record (no key): Cases\<date>_<PC>\install-jobs.log
  - Diagnose and cleanup reports: OfficeDiag_<date> / OfficeCleanup_<date> on the Desktop.

Desktop shortcut
----------------
On each run the script looks for Desktop\Debug\office-install-tool.lnk (it points at the
folder that holds all the dates). If it is missing it asks: Put a shortcut to the logs in Desktop\Debug? (Y/n). Enter
creates it, n skips it (it asks again next run).

Sending a log for debugging
---------------------------
Copy the newest debug-install-*.log into debug\office\ in the project folder.
A typed product key is never echoed (hidden input), and any key-shaped text is replaced
with XXXXX-XXXXX-XXXXX-XXXXX-XXXXX when the run ends. Delete the files in the logs
folder when you are done.
