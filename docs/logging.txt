DEBUG LOGGING
=============

Debug logging is always on. It cannot be switched off.

Where the logs are
------------------
  %TEMP%\Debug\office-install-tool\<yyyy-MM-dd>\
  (usually C:\Users\<you>\AppData\Local\Temp\Debug\office-install-tool\<yyyy-MM-dd>\)

Desktop\Debug.lnk is a shortcut to %TEMP%\Debug. On each run the script looks for it and, if
it is missing, asks: Put a "Debug" shortcut (to the logs) on the desktop? (Y/n).

One file per window
-------------------
Every window or process starts its own transcript, named <name>-<yyyyMMdd-HHmmss>.log, so a
window that crashes still leaves its own file:

  launcher-...log      the first window, before the administrator relaunch
  install-...log       the elevated main window (menu, questions, install)
  diagnose-...log      the readiness-check window (menu option 2)
  cleanup-...log       the scan / cleanup window (menu options 3 and 4)
  officesetup-<PC>-<date>.log   Office's own setup logs, copied from %TEMP% when the install ends
                       (the Office installer window itself cannot be transcribed)
  crash-<timestamp>.txt   written separately whenever a window hits an unhandled error:
                       message, line, stack trace and the log it belongs to

Everything is written to that one folder, nothing goes to the Desktop except the Debug shortcut:
  OfficeDiag_<timestamp>\       diagnose report (report.txt, report.csv, extracts)
  OfficeCleanup_<timestamp>\    cleanup registry backups, MSI uninstall logs, findings JSON
  install-jobs.log             one-line record per install (no key)
Every run makes new files; old files are never overwritten.
The shared code is lib\Debug-Log.ps1.

Office licenses in the logs
---------------------------
The cleanup scan and the diagnose report list every Office license found, with the install it
belongs to (lib\Office-Licenses.ps1): the licensing service (key's last 5 characters, channel
Retail / OEM / Volume KMS / Volume MAK / Subscription, status), registry registrations, account
(Microsoft 365) licensing with e-mail addresses partly hidden, and the license token cache.
Installs are Click-to-Run (with update channel), MSI or Microsoft Store. A license that matches
no install is reported as an orphan license. Full product keys are never read or printed.

Sending a log for debugging
---------------------------
Copy the newest files into debug\office\ in the project folder. A typed product key is never echoed
(hidden input), and any key-shaped text is replaced with XXXXX-XXXXX-XXXXX-XXXXX-XXXXX when a
window ends. Delete the files in the logs folder when you are done.
